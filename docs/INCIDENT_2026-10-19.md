## BE stop amendment: fixed locally

A BE stop added to an entry-only option group is stored in the group's `ids.sl`.
The entry lots still contain only their entry IDs. Price amendment code selected
the lot path whenever lots existed, so it could not find the aggregate stop.
Eight persisted stop-drag requests failed with `Exit order is no longer working`.
The BE result had reported the stop as `PreSubmitted`.

Use the exact group stop identity when `manual_stop_quantity` is set. Preserve
existing reconciliation, amendment confirmation, order terms and no-replay guards.
REA process capture verified the persisted group-level stop and entry-only lots.
The regression reproduces the original rejection, then checks recovery, one
amendment with unchanged identity/quantity, no replay and cancellation rejection.
134 related mock tests passed; broker acceptance remains unverified.

## Opening delays: unresolved

Chart-opening requests at 21:45:56 and 21:47:28 China time spent approximately
15 seconds executing, then returned 503. The same pattern occurred after the
operator's restart. Opening-hour logs also contain numerous queue-full rejections.
Cold chart history uses synchronous IB history requests on the serialized owner.
This establishes slow chart loading and queue pressure, but does not establish
the full cause of reported tick latency: ticker callbacks can publish during
yielding IB reads. Do not replace or throttle the protected tick delivery path
based on queue timings alone. Opening-load recovery still requires validation.

## Performance dates: unresolved

The inspected cache contained account data through October 16 and S&P 500 data
through October 16, but NASDAQ 100 only through October 15. Curves use the common
date intersection, so the API returned October 15 as its end date. Its six-hour
cache was marked fresh. This is a backend data/alignment limitation, not evidence
that the phone failed to receive a newer curve. No dates or values were fabricated
and no production cache or database was modified.
