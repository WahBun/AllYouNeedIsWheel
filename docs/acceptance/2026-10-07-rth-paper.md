## Follow-up: user-selected option Add policy

The user authorized option entries to default to no TP/SL, and Add only when no
opposite working orders exist. Implemented separate `add_allowed` state: Trim
retains its existing protection requirements. The backend rechecks broker orders,
owned fills, exact reference, direction and quantity before Add. No automatic
protection cancellation. Pending entry/close/reconciliation also blocks another Add.
Web option defaults are off unless the user has explicitly saved a preference.
Native phone binary is unchanged.

## Further RTH acceptance: Add cancellation race and option protection

On the deployed 39f9136 runtime (75a58bd documentation HEAD), MNQ Add repricing
and cancellation were dispatched concurrently against the same pending Add.
IB filled that Add before cancellation: the response explicitly reported the fill,
position became two, and active TP/SL quantities both became two. No filled-unit
protection was canceled. Final close filled and all MNQ test orders were terminal.
This covers the previously missing Add-fill-before-cancel outcome, not every
possible interleaving. Private evidence: `/tmp/wheel-rth-race.jsonl`.

An attempted two-contract protected option entry exposed a broker incompatibility:
the first unit filled, while the second unit bracket and its children became
Inactive. This is a rejected second unit, NOT a partial fill of one broker order.
The intended two-to-one protected Trim could not be certified. New submissions
with more than one option contract and any TP/SL are now rejected before allocating
or sending broker orders. Single-contract protection and multi-contract entries
without protection remain supported. This is a containment fix, not implementation
of aggregate option bracket scaling. Removed option aliases of futures tests that
incorrectly assumed IB accepts this arrangement; the futures coverage remains.

The option TP amendment was acknowledged initially but subsequently became
Cancelled at the broker without a fill; do not classify acknowledgement as exit
completion. The remaining SL was explicitly canceled. Once both exits were
terminal, Add re-enabled and one additional option actually filled (one to two).
The final two-contract close filled and the test position returned to zero. This
also verifies the user's requirement that prior protection must not permanently
block Add after confirmed cancellation. Private evidence is in
`/tmp/wheel-rth-option-trim.jsonl` and `/tmp/wheel-rth-20261007.jsonl`.

A first MNQ submission was rejected before broker writes while authoritative
price increments were unavailable; later broker rules returned. No rejected or
unknown trading request was replayed. Unknown submissions were reconciled by
read-only state before any further action.

Remaining blockers: aggregate stock Add/Trim, multi-contract option protection/
Trim, unprotected option Trim, sustained partial fill of one broker order, and
whole-Gateway in-flight disconnect recovery. The latter remains excluded because
existing user orders share that Gateway. Live remains closed; no phone Run/install.
